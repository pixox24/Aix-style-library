# 风格应用与冲突消解

在需要把用户画面要求与风格组件合成提示词时读取本文件。字段含义见 `schemas/style.schema.json`，请求结构见 `protocol.md`。

## 优先级

1. 用户明确主体、动作、场景、文字、身份/颜色保持要求。
2. 用户明确画幅、镜头、构图、用途。
3. 风格核心（core）视觉特征。
4. 风格支持（support）与点缀（accent）特征。
5. 工具默认值。

这是产品行为要求，不代表把用户要求写在前排就能自动消除语义冲突。

## 分工

Agent 负责语义判断：识别主体与用途、判断“白底”与“雨夜”是否冲突、判断黑白要求与青紫调色是否冲突、提取要逐字保留的文字与比例。脚本负责确定性工作：归一化 ID、校验排除项是否属于当前风格、按固定顺序拼装、去除精确重复的 ID。

脚本不能判断“红色产品是否会被某种光照影响”，也不会替 Agent 理解自由文本。

## 强度

| 强度 | 初始选中组件 |
|---|---|
| `light` | core |
| `balanced` | core + support |
| `strong` | core + support + accent |

随后删除 `resolution` 中的排除项。强度是模板特征覆盖范围，不保证线性视觉变化，也不等于某模型的 stylize/denoise/guidance 数值。

## 拼装顺序

`prepare` 输出 `final_prompt`，各段独占一行，空项略去：

1. `画面内容：<intent.description>`
2. `必须保留：<must_preserve 按原顺序>`
3. `画面中的文字（逐字）：<text_literals 按原顺序>`
4. `视觉风格：<实际选中的 features 按 style.json 顺序>`
5. `画幅比例：<约分后的 aspect_ratio>`
6. `避免出现：<未被排除的 avoid 按原顺序>`

不对中英文做模糊去重；只对明确的组件 ID 和精确重复列表项去重。用户要求出现在画面中的文字保持原始字符。

## 冲突处理

| 用户请求 / 风格特征 | 处理 | 结果 |
|---|---|---|
| 白底产品 / 例图是雨夜街道 | 不提取例图场景，只取视觉组件 | 保留白底与产品 |
| 红色机身必须准确 / 有色光 | 在 `exclude_features` 排除色偏组件并写原因 | `STYLE_ADJUSTED` |
| 9:16 / 工具或旧例子默认 16:9 | 保留 9:16；工具映射另查能力 | 不输出两套矛盾比例 |
| 画中文字“春日限定” / avoid 冲突 | 排除冲突 avoid，逐字传递文字 | `NEGATIVE_ADJUSTED` |
| 正面居中 / 风格默认低机位三分 | 排除构图组件 | 用户构图不被改写 |
| 纯黑白线稿 / 全部核心组件依赖彩色写实 | 不把剩余空模板称为该风格 | `STYLE_NOT_APPLICABLE` |
| 用户请求与 `weak_for` 有交集 | 判断是否仍可完成，可完成则提醒 | 不因弱项标签强制打断 |

保留至少一个 core 只是最低结构条件。若剩余特征已不能代表该风格，仍须解释不适配，不能利用结构检查绕过语义要求。

## 不完整输入

- 仅“使用 0001 风格”：完成选择即可，不强迫用户立刻给主体。
- “用 0001 生成一张图”且无上下文：询问画面内容，不随意选择主体。
- 未指定模型：默认通用提示词；宿主已有明确生成工具时用其支持的能力。
- 未指定比例：保持 null；如“竖版”足够清楚可推断 9:16 并简短说明假设。
- 非核心冲突按优先级处理并告知，不逐项请求许可。
